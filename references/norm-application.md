# 规范解释、意思表示与漏洞处理

请求权基础不是条文检索竞赛。遇到开放概念、合同歧义、规范冲突或法律未明确规定时，按本文件记录推理链，避免把个人直觉包装成法条结论。

## 1. 先判断问题类型

| 类型 | 核心问题 | 首选操作 |
|---|---|---|
| 规范识别 | 哪一规范直接产生目标效果 | 目的效果反推、特别规范检索 |
| 规范解释 | 条文中的概念或边界为何 | 文义起点、体系、目的、历史与合宪性 |
| 意思表示解释 | 当事人实际约定了什么 | 文字、整体条款、交易目的、磋商与履行 |
| 合同补充 | 双方未约定的问题如何处理 | 补充协议、相关条款、交易习惯、任意法 |
| 规范冲突 | 两条规则是否同时适用 | 上位法、特别法、新法、规范目的与排斥关系 |
| 法律漏洞 | 法律未直接规定且非有意沉默 | 类推、目的限缩/扩张、一般条款，严格说明边界 |
| 事实评价 | 已确定规则能否覆盖案件事实 | 要件化涵摄与证明责任 |

## 2. 规范群而非孤立法条

为每个 `basis_id` 建立规范群：

1. **主要规范**：直接产生请求效果；
2. **第一层辅助规范**：定义主体、对象、期限、过错、因果或法律效果；
3. **第二层辅助规范**：解释第一层要件的特别规则；
4. **防御规范**：阻却、消灭、限制或延缓；
5. **反抗辩规范**：排除防御规范；
6. **证明规范与程序规范**：决定谁证明、如何行权和法院能否作出该判项。

报告中应说明各规范之间是参引、补充、排斥、例外还是竞合，不能把同一层次的法条无差别堆叠。

## 3. 解释记录卡

争议解释至少记录：

```text
解释对象：
文本起点：
可能含义 A / B：
体系位置与相邻规范：
规范目的或交易目的：
案件事实对选择的影响：
相反观点及后果：
选择及适用边界：
法源状态：已核 / 待核
```

合同解释要区分“确定已有意思”与“补充双方未约定内容”。格式条款的订入、提示说明、效力控制和不利解释是不同问题，不能合并成一句“格式条款无效”。

## 4. 漏洞处理纪律

只有在以下条件同时具备时才进入漏洞填补：

1. 已遍检可直接适用的成文法、司法解释和合同约定；
2. 法律未规定不是立法者有意排除；
3. 待决情形与参照规范在决定性评价上相同，或者文字覆盖明显超出规范目的；
4. 处理结果不创设应由立法规定的责任类型、连带责任、无过错责任或举证倒置；
5. 公开写明参照对象、相似点、差异点和边界。

无法完成上述论证时，结论只能是“存在学理路径/待核裁判规则”，不得写成确定法。

## 5. 从解释转入证据

解释结论会改变事实相关性。例如“重大违约”若以合同目的是否落空为标准，核心证据就不是违约次数本身，而是义务重要性、替代可能、催告、延误后果与交易目的。每次完成解释，应立刻生成：

- 哪些事实变为控制性事实；
- 哪一方负主张/证明责任；
- 哪些既有材料被激活；
- 是否产生新的 `issue_id/action_id`。
