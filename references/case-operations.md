# 真实案件接收、增量复核与就绪检查

## 1. 首次投料

用户不需要先整理材料。先完成：

1. 建立案件编号、分析基准日、用户立场和案件阶段。
2. 枚举已收到文件、无法打开文件、重复件和疑似缺页件。
3. 为每份材料建立 `source_id`，记录文件名、日期、类型、页数/消息区间、原件状态和保密级别。
4. 只提取会影响主体、请求、要件、抗辩、金额、期限或证据资格的信息。
5. 第一轮先给方向、P0/P1 风险和最小追问，不等待材料“完美齐全”。

禁止要求用户把文件中已经存在的信息重新手工填写。

## 2. 案件状态账本

连续案件维护以下对象：

| 对象 | 编号 | 必备字段 |
|---|---|---|
| 材料 | source_id | 名称、形成时间、来源、定位、完整性、用途 |
| 事实 | fact_id | 内容、版本、主张方、source_id、争议状态 |
| 诉请 | claim_id | 请求人、相对人、法律效果、金额/标的、状态 |
| 基础 | basis_id | 对应 claim_id、规范、位阶、状态、依赖条件 |
| 争点 | issue_id | 待证命题、证明责任、证据、缺口 |
| 动作 | action_id | 对象、动作、目的、期限、责任人、完成标准 |

状态账本是内部工作底稿，不因输出面向客户而省略。给客户的版本可以隐去技术编号。

## 3. 新材料增量复核

收到补充材料后按以下顺序：

1. 登记新增 `source_id` 并检查是否与旧材料冲突。
2. 列出新增、修正、被推翻和仍未知的事实。
3. 只重跑受影响的 `claim_id/basis_id/issue_id`。
4. 更新证据强弱、金额、程序期限和行动优先级。
5. 输出版本变化摘要：`旧结论 → 新结论 → 变化原因 → 下一动作`。

没有变化也要说明“该材料未改变当前结论”及其证明用途，避免用户误以为材料被忽略。

## 4. 对方最强版本压力测试

不预设己方正确。分别检查：

- 是否找错被告、漏列责任主体或请求法律效果不可执行。
- 己方事实版本是否与合同、流水、聊天、前案陈述或自认冲突。
- 对方能否用另一种交易性质解释同一资金流或行为。
- 否认、未发生抗辩、消灭抗辩、行使抗辩能否覆盖全部候选基础。
- 金额计算是否存在重复、期间错误、缺少减损或因果关系。
- 仲裁、管辖、时效、重复起诉、前置程序等是否可先行阻断。
- 即使实体胜诉，是否存在无法保全或无法执行的现实失败。

输出最强攻击、需要预埋的回应、所需证据和仍无法消除的风险。

## 5. 立案/答辩就绪闸门

不要使用虚假总分。逐门判断：

| 闸门 | 判断内容 | 状态 |
|---|---|---|
| 主体与程序 | 当事人、管辖、仲裁、前置、期限、送达 | 通过/附条件/阻断 |
| 诉请与基础 | 法律效果明确、请求权覆盖、竞合处理 | 通过/附条件/阻断 |
| 事实陈述 | 必要事实完整且无未解释矛盾 | 通过/附条件/阻断 |
| 证据 | 控制性要件有证据或合理取证路径 | 通过/附条件/阻断 |
| 金额与范围 | 计算可复核、无重复、范围有依据 | 通过/附条件/阻断/不适用 |
| 执行与止损 | 财产、保全、行为可执行、紧急风险已处理 | 通过/附条件/阻断 |

总判断只用：

- `可提交`：没有阻断项，附条件项已有可控方案。
- `附条件可提交`：可先行提交，但必须同步完成列明动作。
- `暂不建议提交`：存在可能导致败诉、驳回、失权或重大策略损失的阻断项。

## 6. 输出对象切换

- **律师内部版**：保留全部编号、备选路线、不利事实、法源和证据评级。
- **客户沟通版**：先讲方向、风险和需要客户完成的动作，减少术语但不淡化不利结论。
- **起诉准备版**：突出诉请、事实主张、被告、管辖、证据目录、金额和保全。
- **答辩准备版**：逐项对应原告诉请，区分否认、抗辩、备位抗辩、抵销和反诉。
- **庭前准备版**：按争点组织证据、证明责任、质证、发问、对方最强论证和底线方案。

用户没有指定时，默认先给律师内部快速检视，再询问是否需要转换成交付客户或提交法院的文书。

## 7. 保密与外部工具

- 默认本地读取案卷；只为核验现行法、公开主体和公开案例访问外部来源。
- 联网检索使用脱敏关键词，除非用户明确授权使用真实名称或案号。
- 输出给第三方前提示清理身份证号、住址、电话、账户、未公开商业秘密和未成年人信息。
- 不将模型输出描述为已形成律师—客户保密特权或替代律所的信息安全制度。
