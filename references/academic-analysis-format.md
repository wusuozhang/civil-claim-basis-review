# 规范鉴定写作协议

本文件规定完整检视报告第一部分的写法。它把法学院式请求权基础解题改造成律师可复核的规范分析，不复制任何教材题解、案例答案或独特表述。

## 1. 第一部分固定顺序

完整检视先写“第一部分：规范鉴定”，依次包含：

1. **案情**：只写完成法律评价所必需的事实；区分无争议事实、单方陈述、暂定假设与未知事项，并保留 `fact_id/source_id`。
2. **问题**：改写为“谁可否依据《具体规范》第几条第几款第几项或已定位法律行为条款，向谁请求何种法律效果”。主体或法律效果不同，分别设问。
3. **大纲**：先列候选请求权树，再按最终分析顺序排列。每项必须有 `claim_id → basis_id → 直接请求权基础的具体法源 → rule_id`；`rule_id` 不得代替具体法源。
4. **解题**：逐项完成“假设结论—规则—要件—涵摄—阶段结论—最终结论”。

第二部分才进入律师实务检视，包括程序、证据、金额、策略、保全、执行和行动计划。

## 2. 请求权树与排序

大纲不得只列法条。使用下列最小结构：

```text
CLAIM-01 甲向乙请求支付 100 万元
├─ BASIS-01A 依据《某合同》第3条及《某法》第X条第1款的原始履行请求（主位）
│  ├─ 1. 请求权已产生
│  ├─ 2. 请求权未消灭
│  └─ 3. 请求权可实行
├─ BASIS-01B 解除后返还请求（备位，前提：合同已解除）
└─ BASIS-01C 不当得利返还（排斥候选，前提：不存在其他法律根据）
```

排序先处理规范排斥和逻辑前提，再考虑特别规范、要件数量、证明负担与诉讼经济。大纲与解题必须同构：增删或改序一个请求权基础时，另一处同步更新。

## 3. 单项请求权的固定骨架

每项以可证伪的假设句开始：

> 甲可能依据【具体规范/合同条款】请求乙【具体法律效果】。

假设句后先填写：

```text
直接请求权基础：《规范全称》第X条第X款第X项；或《法律行为》第X条（source_id＋定位）
法定法律效果：该规范为何直接产生本项请求权
请求权基础完整性：单条规范完整/规范组合完整＋主体—要件—效果说明
该条款能否直接推出本项请求：能/不能＋理由
其他规则：仅按中文全称列出实际使用的辅助/构成规则、行为归属规则、金额/范围/计价规则、证明规则、抗辩/限制规则和程序规则
现行法核验：官方来源＋核验日期＋时间效力
```

“合同关系”“违约规则”“相关司法解释”“无权占有”“设计变更”等不能填入直接请求权基础。只规定损失范围、计算、证明、归属或程序的条文也不能单独填入直接请求权基础。没有具体法源时只能标 `待核法源`，本路径不得给出“可行”或“附条件可行”。

随后依次检视：

### 1. 请求权已产生

- 1.1 主要规范的适用范围与主体结构；
- 1.2 每一积极要件；
- 1.3 权利未发生的阻却规范；
- 1.4 产生层阶段结论。

### 2. 请求权未消灭

- 履行、抵销、提存、免除、混同、解除后的变更、和解/更新等；
- 只检视有事实线索或依法必须审查的消灭事由；
- 以阶段结论收束。

### 3. 请求权可实行

- 期限是否届满、条件是否成就；
- 同时履行、先履行、不安、先诉等抗辩权；
- 诉讼时效抗辩、法定行权期间、责任限制及其他延期/限制；
- 以阶段结论收束。

### 4. 结论

结论必须与开头假设一一对应，并写明状态：`满足`、`不满足`、`待证`、`无争议`、`无需检视`、`待核法源`。

如果前置要件确定不满足，可以停止后续实质涵摄，但仍保留标题并标记“无需检视”，避免读者误以为遗漏。

## 4. 每个争点的鉴定式微结构

一个控制性争点按以下顺序写：

1. **问题**：本项是否满足某要件。
2. **规则**：定义、判断因素、证明责任及例外；精确到法律名称、条、款、项，必要时说明司法解释或学理来源。
3. **涵摄**：把具有法律意义的事实逐一与要件对照；同时写有利与不利事实，不用“显然”“不言而喻”代替论证。
4. **小结**：只回答本争点，并注明事实/证据/法源依赖。

不得采用“抄一段法条＋复述一遍案情＋直接下结论”的伪涵摄。

## 5. 法源与脚注纪律

- 成文法能够解决时，优先引用现行成文法和司法解释；法条必须核到条、款、项，不能确认则标 `待核法源`。
- 合同等法律行为作为直接基础时，必须写文件名、条款号及 `source_id＋页码/段落`；无条款号时写小标题、必要原文首尾和材料定位。
- 每个法源用中文标明其属于直接请求权基础、辅助/构成规则、行为归属规则、金额/范围/计价规则、证明规则、抗辩/限制规则或程序规则；计价、证明、归属或程序规则不能单独冒充直接请求权基础。
- 成文法存在开放概念、冲突或漏洞时，才引入解释、类推、目的限缩或学理，并说明选择理由与相反观点。
- 指导性案例、入库参考案例、公报/典型案例和普通裁判分层标识，不把裁判摘要当成法条。
- 脚注用于法源、案例和必要学理，不承载尚未写进正文的关键论证。
- 事实脚注或括注必须能回到 `source_id＋页码/段落/时间戳`。

## 6. 学术格式与真实案件的接口

规范鉴定回答“在给定事实版本下，法律上是否成立”；它不自动等于“法院会支持”。因此每个 `basis_id` 在第二部分继续接受五次转换：

`实体规范成立 → 当事人陈述充足 → 争议命题可证 → 程序上可走 → 判项与执行可实现`

第一部分出现的每个 `待证` 应进入第二部分的 `issue_id`；每个主体、金额、期限和前置程序疑点，应进入程序或行动模块。第二部分不得新造与第一部分无关的核心请求权；确有新增时，回写大纲与解题。

## 7. 简化规则

- **完整检视**：必须使用全部四段和三层四步。
- **快速检视**：可压缩为“问题—候选基础—关键要件—暂定结论”，但至少保留一个假设句和产生/消灭/可实行状态。
- **单点问答**：只展开被问争点，但说明它位于哪一 `claim_id/basis_id` 的哪一层。
- **被告模式**：仍从请求权是否产生开始，不得只罗列抗辩；对方多个基础须做防御覆盖。
