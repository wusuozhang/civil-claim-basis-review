# 具体请求权基础与规范功能闸门

## 1. 硬标准

请求权基础不是事实标签、案由、法领域、规则卡名称或“相关规定”。它必须是能够直接产生所请求法律效果的现行规范，包括：

- 已定位的合同、遗嘱、决议等法律行为条款；
- 精确到法律、行政法规或司法解释的条、款、项；
- 经明确参引后共同产生法律效果的规范组合。

对每个候选基础先问：

> 假定该规范的全部要件均满足，能否直接推出请求人有权要求相对人承担本项法律效果？

不能直接推出的，只能列为辅助、归属、计量、证明、防御或程序规范，不得单独命名为 `basis_id`。

还须检查请求权基础是否完整：该条本身或者其明示参引的规范组合，能否识别请求权主体、责任发生要件和请求内容。只规定“损失赔偿额如何计算”“某事实如何推定”“行为归属于谁”“由哪个法院审理”的条文，均预设其他责任基础，不能单独作为直接请求权基础。需要两条以上规范共同闭合时，全部列入“直接请求权基础的规范组合”，并说明各自承担的产生要件或法律效果；不能把范围规范硬说成产生规范。

下列表述不能作为最终请求权基础：

- “依据合同关系”“依据建设工程规则”“依据侵权规则”；
- “依据设计变更、违约行为、无权占有”等事实或评价标签；
- “依据相关法律、司法解释、公平原则”；
- 仅列 `rule_id`、案由、证据名称或裁判观点。

## 2. 每个 basis_id 的必填卡

```text
claim_id / basis_id：
请求人 → 相对人 → 具体法律效果：
直接请求权基础：《规范全称》第X条第X款第X项；或《法律行为名称》第X条/第X款（source_id＋定位）
法定法律效果：该规范在本案中直接产生何种请求权
请求权基础完整性：单条规范完整/规范组合完整＋主体—要件—效果说明
辅助/构成规则：
行为归属规则：
金额/范围/计价规则：
证明规则：
抗辩/限制规则：
程序规则：
该条款能否直接推出本项请求：能/不能＋理由
现行法核验：官方来源＋核验日期＋时间效力
```

只有实际用到的辅助栏才展开，但直接请求权基础、法定法律效果、请求权基础完整性、“该条款能否直接推出本项请求”和现行法核验不得省略。

常见误判：

- 责任范围、损失计算、利息起算或金额调整条文通常属于金额/范围/计价规则；若没有责任发生条文或法律行为条款，不足以单独支持给付判项。
- 举证责任、推定、书面形式、鉴定或证据采信条文属于证明规则，不能因为它决定胜负就当作直接请求权基础。
- 代理、代表、职务行为、追认等条文属于行为归属规则；它们只能把另一项法律行为或责任归属于相对人。
- 管辖、保全、诉讼参加、鉴定程序和执行条文属于程序规则。
- 定义、解释、计价或证明规范可以与真正的责任发生规范共同出现，但必须分别标注功能。

## 3. 引用精度

- 成文法写明规范全称和条、款、项；原条文没有款、项时不虚构层级。
- 司法解释写明完整名称、文号（能够核实时）和条、款、项。
- 合同等法律行为写明文件名、条款号并回指 `source_id＋页码/段落`；无编号时引用小标题、原文首尾和材料定位。
- 多条规范共同产生效果时，说明参引、补充、排斥或竞合关系，不能无差别堆叠。
- 规则卡的“规范锚点”只用于检索。正式报告必须回到官方现行法和案件法律行为。
- 专业领域 Skill 只负责补足候选规范和特殊要件；其输出仍须通过本闸门。只返回争点名称、法领域或条文群时，应继续核法，不得原样写入直接请求权基础。

## 4. 法源暂时无法确认

无法确认具体法源时：

1. 标记 `待核法源`，不得凭记忆补条号；
2. 不把抽象规范方向包装成已经确认的直接请求权基础；
3. 将该路径结论降级为 `待核法源`，不得写“可行”或“附条件可行”；
4. 记录需要检索的规范名称、目标法律效果和官方入口；
5. 完整报告交付前原则上完成核验。确因官方来源不可访问而未完成时，明确列为阻断项。

## 5. 问题、大纲与解题同构

同一请求权基础必须在三处使用同一具体法源：

1. **问题**：谁可否依据《某法》第X条第X款向谁请求何效果；
2. **大纲**：`claim_id → basis_id → 直接请求权基础的具体法源 → 主位/备位`；
3. **解题**：以相同法源开始，完成产生、未消灭、可实行和镜像结论。

如果解题中发现直接法源错误、遗漏或需改序，必须同步修改问题和大纲。

## 6. 两个通用反例

错误：

> 甲可依据违约规则请求乙赔偿。

正确结构：

> 甲可否依据《合同》违约责任条款第X条及《某法》第X条第X款，请求乙赔偿某项损失？其中损失范围条文列为金额/范围/计价规则，举证责任规则列为证明规则。

错误：

> 甲可依据无权占有请求乙返还房屋。

正确结构：

> 先分别检索合同返还、物权返还或占有保护的具体规范；只有能够直接赋予甲对乙返还请求权的规范才建立 `basis_id`。“无权占有”只是待涵摄事实评价。
