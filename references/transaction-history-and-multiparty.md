# 交易历史、多主体与请求权竞合

复杂案件经常不是规则难，而是主体、时间与财产流转没有拆开。本文件与请求权基础法并行使用，防止把一段商业故事压成一个“合同关系”。

## 1. 四张图

复杂案件至少建立：

1. **主体—授权图**：签约人、名义主体、实际履行人、受领人、控制人、担保人、第三人；
2. **合同—法律关系图**：每一份合同、单方行为、代理/代表、债权让与和担保关系；
3. **物与资金流图**：谁在何时交付、登记、占有、付款、代付、收款；
4. **诉请—责任图**：每个请求人向哪个相对人主张什么效果，是否连带、按份、补充或顺位。

图之间不一致之处通常就是核心争点：签约人未收款、收款人非债权人、施工人非合同方、登记人非付款人、指令人无权限。

## 2. 时间切片

对于所有权、占有、债权转让、解除和多重买卖，至少在以下节点分别判断权利状态：

`订约前 → 订约时 → 交付/登记时 → 违约或处分时 → 解除/通知时 → 起诉时`

不得用起诉时状态倒推订约时事实，也不得以先订合同直接推出后来仍享有所有权或交付请求。

## 3. 多主体拆分

- 主体不同，原则上另建 `claim_id`；
- 同一被告承担不同责任性质，分别建 `basis_id`；
- 法定代表、代理、职务行为、第三人履行、债务加入、保证和共同侵权分别定性；
- 连带、补充、按份、顺位必须有明确规范，不能因为“都参与了”而合并责任；
- 内部追偿是新的请求，不应混入受害人的外部请求。

## 4. 竞合类型

| 类型 | 处理 |
|---|---|
| 规范排斥 | 特别清算、占有人清算等排除一般不当得利；写明被排斥原因 |
| 逻辑前提 | 先审合同/解除/物权状态，再审返还或赔偿 |
| 择一 | 两种责任不能同时获得，设计主位/备位或行权选择 |
| 聚合 | 不同损害或不同法律效果可以同时请求，但逐项去重 |
| 同一诉请多重基础 | 诉请相同、理由并列；防御须覆盖全部基础 |
| 不同诉请不同基础 | 分别计算诉讼标的、管辖、费用、保全及判项 |
| 实体与程序交叉 | 实体权利存在不代表可在同一诉中合并或以当前主体主张 |

## 5. 典型高风险结构

### 一物数卖

分别审每份原因合同、物权公示、占有、处分权/善意取得、第三人恶意与不能履行后的返款赔偿。先买受人不当然优于已登记或已交付的后买受人。

### 转租与实际占有人

出租人对承租人的合同请求、对次承租人/实际占有人的物权或占有请求分别建立。租赁届满、解除、转租授权和第三人占有权源不能合并判断。

### 名义主体与实际履行人

合同相对性是起点，但应继续查代理/代表、债权让与、债务加入、第三人利益、事实合同、法定责任和特别法。实际付款、盖章、签证或管理并不单独决定合同主体。

### 多人侵权或担保

先找法定责任连接点，再确定外部责任形态和内部追偿。无法确认某一行为人不等于当然由全部相关者连带承担。

## 6. 输出要求

每个多主体案件至少输出一张表：

| claim_id | 请求人 | 相对人 | 行为/身份连接点 | 主要基础 | 责任形态 | 关键证据 | 竞合/追偿 |
|---|---|---|---|---|---|---|---|

如果主体身份尚未查清，用情景分支，不把“项目负责人”“实际控制人”“收款人”等事实标签直接等同为民事责任身份。
