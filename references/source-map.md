# 公开法源、规则来源与私有资料边界

目录：一、公开运行承诺；二、公开规则库组成；三、一级官方法源入口；四、规则卡来源标记；五、公开边界；六、私有增强；七、更新闭环。

## 1. 公开运行承诺

本 Skill 的正常运行只依赖 Skill 目录内的 `SKILL.md`、`references/`、`assets/` 和 `scripts/`。不得把外部教材、整书 OCR、数据库批注或用户本机绝对路径设为必需依赖。

外部资料只能用于：

- 逐案核验现行法和公开案例；
- 用户主动提供的案件材料；
- 用户合法持有并在本地配置的私有增强资料。

私有增强资料不可用时，继续使用公开规则库完成检视，并把尚未核实的具体条文、特别法或案例标为待核；不得要求用户上传整本教材才能分析。

## 4. 规则卡的来源标记

公开规则卡采用独立的办案任务结构，不复制第三方教材章节。维护规则时记录以下来源类型：

- `STATUTE`：法律、行政法规、司法解释等官方规范；
- `OFFICIAL_CASE`：指导性案例、人民法院案例库、公报或典型案例；
- `SELF_AUTHORED`：基于办案流程独立创作的要件、证据和策略表达；
- `SPECIALIST_REQUIRED`：只完成总控，必须追加专业法源或专业 Skill；
- `PRIVATE_OPTIONAL`：用户本地合法资料，仅作增强，不进入公开仓库。

新规则卡至少应有一个 `STATUTE` 或明确标记 `SPECIALIST_REQUIRED`。学术观点和普通案例不能单独作为现行法结论的唯一依据。

规则库的规范鉴定格式属于自行设计的任务协议：只吸收通行的法律方法（提出假设、列明规范、要件涵摄、阶段结论），不收录课程讲义、题目、示范答案、批注、页眉页脚或独特表述。

## 5. 可公开与不得内置的内容

### 可以公开

- 自行创作的 Skill 工作流、规则卡、模板、测试和脚本；
- 法律法规及司法性质官方文件的必要文本、条号和官方链接；
- 对公开裁判的自行概括、争点索引和必要短引；
- 书名、作者、版本、出版社、ISBN、页码等书目信息；
- 自编、合成或取得授权的测试案例。

### 不得作为公开运行时资源内置

- 未获许可的整本书 OCR、Markdown、扫描件或电子书；
- 足以替代原书的连续摘录、逐章改写、案例答案和独创性编排；
- 商业数据库独创的裁判要旨、批注、分类或批量导出内容；
- 用户案卷、身份证明、商业秘密和未脱敏个人信息；
- 任何指向开发者本机私有书库的绝对路径。

引用第三方作品时遵循必要、适量、注明作者和作品、不得替代原作正常使用的原则。开源许可证只覆盖有权许可的自行创作内容，不得宣称覆盖第三方作品。

## 6. 私有增强接口

用户主动配置私有资料时：

1. 只在本地检索，不上传完整资料到外部服务；
2. 为资料分配 `source_id` 并标记 `PRIVATE_OPTIONAL`；
3. 只提取与当前 `rule_id/issue_id` 有关的必要信息；
4. 具体法律结论仍回到官方现行法核验；
5. 输出中区分法源、案例、学理观点和用户材料；
6. 私有资料缺失、移动或删除，不影响公开规则库继续运行。

## 7. 规则库更新闭环

发现规则变化或分析缺口时：

1. 记录受影响的 `rule_id` 和案件场景；
2. 用官方现行法确认变化，不从教材直接覆盖；
3. 更新产生要件、防御、效果、证据或特别法边界；
4. 新增或修订版权洁净的行为测试；
5. 运行资源、规则编号、私有依赖和报告结构校验；
6. 在案件增量复核中说明“旧结论 → 新结论 → 变化原因 → 下一动作”。
